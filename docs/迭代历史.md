## v1.7 —— 界面自适应 + 数据安全加固（最新）

### 主题一：界面 DPI 自适应改造

**需求**：软件窗口的字体和大小需要自适应，避免在不同分辨率的机器上展示不全。

**方案**：显式换算（`UiScale`），**不用** WinForms 的 `AutoScaleMode.Dpi`。

> **决策理由**：本项目界面全是纯代码构建、无设计器基准信息。WinForms 自动缩放依赖设计时的 `AutoScaleDimensions`，纯代码场景下行为不确定且容易双重缩放。
> 显式换算行为完全确定、可被探针逐项测量验证。所有窗体统一 `AutoScaleMode = None`。

**核心实现 `Services/UiScale.cs`**：

| API | 作用 |
|---|---|
| `Factor` | 系统 DPI / 96（`GetDpiForSystem` + `GetDeviceCaps` 兜底）；`MYREMOTE_UI_SCALE` 可覆盖 |
| `S(int/Size/Padding)` | 设计像素 → 实际像素 |
| `SetFormSize(form, w, h, minW, minH)` | 缩放 + 裁剪到工作区（**最小尺寸也要裁剪**，否则小屏+高DPI必然超屏） |
| `WorkingArea()` | Win32 `SystemParametersInfo(SPI_GETWORKAREA)`（线程安全，`Screen` 组件在线程池不安全） |
| `SetColumns()` / `AutoFillLastColumn()` | 列表列宽缩放 + 末列补满 |
| `AutoFit(Button, minWidth)` | 按钮按文字自动撑宽（**高 DPI 下中文变宽，固定宽度会切字**） |
| `Describe()` | 供界面/日志显示当前缩放 |

**改造范围**：7 个窗体 + 2 个内嵌对话框，全部硬编码尺寸/字体替换为 `UiScale.S()`。

**🔴 关键 bug 修复（截图实测发现）**

> **诊断窗体「详情与解决指引」面板整块消失**
>
> **根因**：WinForms 停靠规则是**后添加的控件优先占边缘**。原代码先 `Add(detailPanel)` 再 `Add(_list)`，`Dock=Fill` 的列表把 `Dock=Bottom` 的详情面板挤没了。
> **修复**：`Dock=Fill` 的控件必须**最先** `Add()`。
> **教训**：这是 WinForms 的经典陷阱，且**只有真实渲染才能发现** —— 编译通过、控件在 `Controls` 集合里、属性都对，就是看不见。

**新增验证手段（探针）**：

| 模式 | 作用 |
|---|---|
| `--ui` | 界面审计：真实实例化每个窗体并 `Show()`，检查 ①窗体超屏 ②子控件溢出 ③工具条藏按钮（Flow 布局按换行行数核算高度）④按钮文字被切（`TextRenderer` 实测宽度） |
| `--shot [目录]` | `DrawToBitmap` 保存每个窗体 PNG，人工核对 |

> **踩坑**：`ScaleFonts` 递归时未显式设置字体的子控件返回父控件的**同一字体引用**，逐层重复放大导致指数级失真（2.5×2.5）。
> **修复**：`ReferenceEquals(f, inheritedFrom)` 时跳过继承字体。

**验证结果**：布局矩阵 **11/11 全绿**（100%/125%/150%/175%/200%/250%/300%/400% × 1280×720~4K）。

### 主题二：🔴 P0 级缺陷 —— 快照与结果文件全是空的

**这是本项目迄今最严重的缺陷，因为它会**主动破坏系统**。**

**发现过程**：全功能回归时检查用户真实数据目录 `%APPDATA%\MyRemote\Rollback\`，发现 5 个文件全部是 **2 字节的 `{}`**：

```
snapshot_20261018195409.json      2 字节
snapshot_20261018203233.json      2 字节
last.json                         2 字节
repair_result_20261018195406.json 2 字节
repair_result_20261018203230.json 2 字节
```

**根因**：

> **`System.Text.Json` 默认不序列化 public 字段，只序列化属性。**
>
> `RepairService` 中的 `RepairResult` / `ItemResult` / `SnapshotInfo` / `RepairSnapshot` 全部定义为 **public 字段**：
> ```csharp
> public class RepairSnapshot
> {
>     public DateTime Time;          // ❌ 字段 —— 不被序列化
>     public int RdpDeny;            // ❌
>     ...
> }
> ```
> 序列化结果就是 `{}`。文件写成功了、大小非零、反序列化也不报错 —— 所以一直没被发现。

**危险性分析（为什么是 P0）**：

空快照若被用户用于「一键恢复」，会反序列化出一个**全默认值**的对象：

| 字段 | 默认值 | 恢复时的动作 | 后果 |
|---|---|---|---|
| `RdpDeny` | `0` | 设置 `fDenyTSConnections=0` | 开启远程桌面（可能不是用户想要的状态） |
| `TermStart` | `0` | 把 TermService 设为启动类型 0（无效值） | 服务配置被改坏 |
| `DefFwRulesWasEnabled` | `false` | 认为默认防火墙规则原本是禁用的 | **重新放开"任何地址"作用域** → 端口暴露 |
| `NicPowerJson` | `null` | 网卡节能恢复失败 | 部分网卡设置错乱 |

**最致命的是在远程场景下**：用户点"恢复"本意是回退某次修复，结果系统按默认值被重写，**远程连接直接断开，且无法再连回去**（人在外地就彻底失联）。

**修复（三重防护）**：

1. **全部字段改属性** —— 所有数据类改为 `{ get; set; }` 属性
2. **恢复前校验** —— 新增 `ExplainInvalidSnapshot()` 检查，任一不满足即拒绝执行：
   - `Time == default` → "缺少捕获时间（文件可能是空对象或残缺的旧格式）"
   - `AppVersion` 为空 → "缺少版本信息"
   - `NicPowerJson == null` → "缺少网卡电源设置字段"
3. **历史文件隔离** —— 用户真实的 5 个空快照被移到 `Rollback\_invalid\`（保留现场，不再被恢复逻辑触及）

**验证**：

- 探针 `--snapshot` 输出：快照从 **2 字节** 变为 **392 字节完整 JSON**，含全部关键字段
- **负面测试**：用交付版 exe 对 `{}` 空快照执行 `--restore` → 正确拒绝，结果 JSON 明确写着"已中止恢复，未改动任何系统设置"
- 新增回归测试：断言快照 JSON 包含 `RdpDeny`/`TermStart`/`DefFwRulesWasEnabled`/`NicPowerJson` 等所有字段

> **教训**：序列化缺陷是**静默**的 —— 不报错、不崩溃、文件也存在。只有主动检查内容才能发现。
> **推论**：所有"写文件"的功能都应该有"读回来验证"的测试。这是 `--snapshot` 模式存在的意义。

### 主题三：并发与健壮性修复

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | **并发保存设备会丢数据**（实测 12 个并发写只剩 2 个存活） | `DeviceStore.Save` 无锁，多个线程同时走"读-改-写" | 加 `lock` 串行化；验证后 13 个设备全部存活 |
| 2 | `CredentialVault.SecretsFile` 无视 `OverrideDir` | 路径被缓存为 `static readonly`，首次访问后固定 | 改为**动态属性**，每次解析 |
| 3 | **托盘图标泄漏** | `MainForm` 没有 `Dispose` 重写，`NotifyIcon` 未释放 | 补 `Dispose` + `CreateTrayIcon` 开关（测试用） |
| 4 | 测试会触发真实 RDP 连接 | `SessionForm` 的 `Shown` 事件无条件自动连接 | 加 `AutoConnectOnShown` 静态开关 |
| 5 | `.corrupt-*` 文件被丢弃 | 损坏恢复成功后删除了现场文件 | 改为**保留**（排查用），并改进留存逻辑 |

- 首页新增「Tailscale 登录」按钮

**🔴 真机探针取证发现的 3 个关键 bug（都会导致误报/漏修）**

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | **防火墙检测全部失效**（明明有规则却报"未检测到"） | 项目启用 `InvariantGlobalization=true` 时，`CultureInfo.CurrentCulture.TextInfo.OEMCodePage` 返回 **437**，而中文系统实际是 **936** → netsh 中文输出被按错误代码页解码 | 改用 Win32 API `GetACP()`/`GetOEMCP()` 取真实代码页 + 双通道解码（先 OEM 后 ANSI，按乱码特征自动切换） |
| 2 | 防火墙作用域判断失败 | netsh 实际字段是「远程 IP」（不带"地址"），代码里写的是「远程 IP 地址」 | 修正字段名 |
| 3 | **`Get-NetFirewallRule` / `Get-NetAdapterPowerManagement` 在目标机完全不可用**（返回 0 条） | 系统版本（Win10 IoT LTSC）的 PowerShell cmdlet 问题 | 修复动作与快照检测全部改回 **netsh 通道**（按规则名称逐条操作，跨语言稳定）；网卡节能增加注册表兜底 |

**其他修复**：

- `RunPsFile` 改为 `-EncodedCommand`（Base64/UTF-16LE），彻底绕过 .ps1 文件编码与执行策略问题
- 防火墙修复/恢复改为**按规则名逐条处理**，不再依赖本地化组名

**识别出的真实待修项**：`远程桌面 - 用户模式(TCP-In)` 与 `(UDP-In)` 两条系统规则对"任何地址"开放，需禁用。

## v1.6 —— 全量复测与缺陷修复

对全部源码逐文件复测（16 个源文件 + 部署脚本），修复 **19 处问题**：

### 一、致命（功能直接不可用）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | **首次保存设备必崩** | `DeviceStore.Save` 用 `File.Replace`，该 API **要求目标文件已存在**；第一次"添加设备"时 `devices.json` 尚不存在 → `FileNotFoundException` | 不存在时用 `File.Move` |

### 二、安全

| # | 问题 | 修复 |
|---|---|---|
| 3 | `cmdkey /pass:xxx` 明文回退会把密码暴露在进程命令行 | **彻底移除回退**，仅记日志 |
| 4 | 防火墙暴露判定被掩盖（"存在 Tailscale 规则就判安全"） | 改为"只要存在一条 `RemoteAddress=Any` 的 3389 放行规则即告警" |
| 5 | 一键恢复可能重新放开 Any 作用域 | `DefaultGroupEnabled` 旧实现只要输出里出现"已启用"就返回 true（值为"否"时也有该行）→ 改为**逐块解析**"已启用 是/否" |

### 三、正确性（中文系统环境）

| # | 问题 | 根因 | 修复 |

## 经验总结

### 一、这个项目踩过的坑可以归为五类

| 类别 | 典型案例 | 教训 |
|---|---|---|
| **WinForms 陷阱** | `Dock=Fill` 添加顺序、`ScaleFonts` 指数放大 | UI 问题**必须真实渲染才能发现**，编译通过≠正确 |
| **序列化陷阱** | public 字段不被 `System.Text.Json` 序列化 | 写文件功能必须有"读回来验证"的测试 |
| **本地化陷阱** | 代码页 437 vs 936、`ProductName` 找 "Pro"、`powercfg` 中文输出 | 不要解析本地化文本；用注册表 / `EditionID` / Win32 API |
| **环境差异** | CLSID 未注册、Tailscale 改安装目录、PowerShell cmdlet 返回空 | 永远不要硬编码；运行期探测 + 多路径 fallback |
| **并发与资源** | 并发写丢数据、COM 对象泄漏、托盘图标泄漏 | 写操作加锁；资源显式释放 |

### 二、验证方法论（这是最值得继承的部分）

> **不靠"编译通过"判断正确性，靠"真实测量 + 真实渲染 + 负面测试"。**

| 手段 | 发现过什么 |
|---|---|
| `--ui` 真实渲染审计 | 诊断窗体详情面板消失（肉眼可见但静态检查发现不了） |
| `--shot` 截图人工核对 | DPI 下的视觉问题 |
| `--func` 490 项断言 | 序列化缺陷、并发丢数据、缓存路径错误 |
| `--snapshot` 端到端 | **P0 空快照问题**（只有检查文件内容才发现的） |
| 负面测试（喂坏数据） | 验证安全防护真的生效（空快照确实被拒绝） |
| 真机探针取证 | 防火墙检测失效（代码页问题）、CLSID 不可用、Tailscale 目录变更 |

### 三、给接手者的三条建议

1. **不要删掉探针工程** —— 它是这个项目质量的主要保障。改动后跑一遍 `--func`，几分钟能省几小时。
2. **遇到"奇怪的处理"先查本文** —— 比如"为什么网卡节能要读注册表""为什么 RDP CLSID 要动态探测"，都有原因。
3. **交付前跑完检查清单** —— 见 [开发与发布指南 §7](开发与发布指南.md)。历史上交付旧版 exe、漏 `IncludeNativeLibrariesForSelfExtract` 都发生过。
