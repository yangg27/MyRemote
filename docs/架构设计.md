## 一、设计哲学（先读这段，后面全好懂）

整个项目建立在三个"不自研"的判断上：

| 判断 | 理由 |
|---|---|
| **不自研远程桌面协议** | Windows RDP 已提供画面传输、图形压缩、UDP 传输、多显示器、剪贴板、外设重定向、GPU 加速。自研等于重做微软十年的工程 |
| **不自研文件传输引擎** | SMB 3.1.1 自带加密、签名、缓存、并发、错误恢复。自研只会更慢更不安全 |
| **不自研虚拟组网** | Tailscale（WireGuard 内核）负责打洞与加密隧道，客户端 BSD-3 开源，免费版设备数无限 |

**所以 MyRemote 只做四件事：**

1. **连接管理** —— 设备列表、凭据、在线探测
2. **会话宿主** —— 把 RDP ActiveX 控件塞进自己的窗口，加上全屏/重连/画质控制
3. **文件管理 UI** —— 双栏界面 + 传输调度（底层走 SMB）
4. **环境治理** —— 诊断 + 一键修复 + 快照回退（这才是真正花时间的地方）

这个边界让项目能用 6000 行做到商业软件的核心体验。**任何新需求先问：能否复用系统能力？** 能，就别写。

## 三、关键数据流

### 3.1 设备与凭据存储

```
MainForm ──► DeviceStore ──────► %APPDATA%\MyRemote\devices.json
   │                                   （明文 JSON，原子写 + .bak 备份）
   └──────► CredentialVault ──► DPAPI ──► %APPDATA%\MyRemote\secrets.json
                                          （加密 + Hidden + NTFS ACL 收紧）
```

**DeviceStore 的写入策略**（这里踩过坑）：

| 场景 | 处理 |
|---|---|
| 首次保存（文件不存在） | `File.Move(tmp, target)` —— **不能用 `File.Replace`**，它要求目标已存在（v1.6 修过这个 bug） |
| 后续保存 | 写 `.tmp` → `File.Replace(tmp, target, bak)` |
| 解析失败 | 原文件另存为 `.corrupt-{时间戳}` 现场，然后返回空列表（v1.7 改进：**保留**损坏文件供排查，而不是丢弃后覆写） |
| 并发保存 | `lock` 串行化（v1.7 新增；此前并发写会互相覆盖导致设备丢失） |

**CredentialVault 的路径问题**（v1.7 修）：早期把 `SecretsFile` 缓存成 `static readonly`，导致测试覆盖 `AppPaths.OverrideDir` 后仍写到真实路径。现在改为**动态属性**，每次读取时解析。

### 3.2 RDP 会话

```
SessionForm ──► RdpClientDetector.ResolveClsid()   ← 运行期探测可用控件
     │                    （候选表 → 注册表扫描兜底，结果缓存）
     ▼
RdpHost (AxHost)  ──► MsRdpClient ActiveX
     │                    ├── Server / UserName / Domain / RDPPort
     │                    ├── AdvancedSettings9.ClearTextPassword
     │                    ├── RedirectDrives / RedirectClipboard
     │                    ├── SmartSizing=true（窗口自适应缩放）
     │                    ├── AuthenticationLevel=2（防中间人）
     │                    ├── EnableCredSspSupport=true（NLA）
     │                    └── DesktopWidth/Height / ColorDepth
     ▼
状态轮询（1 秒）─► oc.Connected 0/1/2/3 ──► 更新标题/看门狗/重连
```

**为什么用 COM 后期绑定**（`Type.GetTypeFromProgID` + 反射）而不是编译期引用：

> 编译期引用 Windows COM 组件需要 `tlbimp`，无法在非 Windows 环境完成。
> 后期绑定让项目可以在 Linux 构建机上交叉编译出 Windows 可执行文件 —— 这是"交付成品 exe、用户无需装开发工具"的前提。

**为什么需要 RdpClientDetector**（v1.6 新增）：

> 早期硬编码 `MsRdpClient9` 的 `NotSafeForScripting` 变体 CLSID，在 Windows 10 IoT 企业版 LTSC 上未注册，报 `0x80040154 没有注册类`。
> 现在改为运行期探测：候选表（v12/v11/v10/v9/v8/v7…按优先级）→ 逐个 `Type.GetTypeFromProgID` 尝试 → 失败则扫注册表 `HKCR\CLSID` 找可用的 `MsRdpClient` → 结果缓存。
> `SessionForm.BeginConnect()` 前置检查，不可用时给友好报错（含 `regsvr32` / `sfc` 指引）。

**看门狗与重连**（v1.6 修过两个 bug）：

- 首次连接 15 秒无进展 → 主动断开并提示（不再永久卡在"正在连接"）
- 自动重连**带 `_reconnectPending` 闸门** —— 早期每秒轮询都调用 `ScheduleAutoReconnect`，每次都累加次数并重建定时器，5 次机会 5 秒内耗尽
- 重连时重置 `_connectedOnce` 使看门狗同样生效
- 重连/切换画质时 **移除并 Dispose 旧 `RdpHost`**（早期会泄漏 COM 对象）

### 3.3 SMB 文件传输

```
FileManagerForm ──► NetworkShareHelper.AddCredential(CredWrite)
     │                        （CRED_TYPE_DOMAIN_PASSWORD + ENTERPRISE 持久化）
     │                         ⚠ 密码必须用 Encoding.Unicode（UTF-16）——v1.6 修过
     ▼
UNC 路径 \\host\share
     ▼
SmbTransferService.CopyFileAsync / CopyDirectoryAsync
     │
     └── 写 .mrtmp 临时文件 → 校验大小一致 → File.Move(overwrite:true) 原子替换
         失败/取消 → 删除临时文件，目标保持原状
```

**为什么不用 RDP 的磁盘重定向**：它依附于远程桌面会话（必须建会话、拖拽必须在会话窗口内、无法后台传输）。需求明确要求"独立窗口"，故选 SMB。

> ⚠️ **安全红线**：445 端口绝对不得暴露公网。SMB 是永恒之蓝等蠕虫的主要传播面。
> 防火墙放行规则的作用域必须严格限定为 Tailscale 网段 `100.64.0.0/10`。

### 3.4 一键修复 / 恢复（最复杂的链路）

```
DiagnosticsForm ──► RepairService.RequestRepairAsync(ids)
                        │
                   isAdmin? ──是──► ExecuteRepair(ids, resultPath)  直接执行
                        │
                        否
                        ▼
                  SpawnElevatedAsync  ──► runas 拉起自身
                        │                  MyRemote.exe --repair --items "..." --result "..."
                        │                         │
                        │                         ▼
                        │                  Program.RunHeadlessRepair
                        │                    （_headless=true，绝不弹窗——否则父进程卡死）
                        │                         │
                        │                    CaptureSnapshot → SaveSnapshot
                        │                         │
                        │                    foreach id → FixItem(id, snap)
                        │                         │
                        │                    WriteResultFile(resultPath)
                        │                         ▼
                   ReadResultFile ◄──────── 子进程退出
                        │
                   回填 UI（含 UserCancelled 判定：UAC 取消 1223）
```

**快照内容**（`RepairSnapshot`，全部为**属性**——见下方序列化陷阱）：

| 字段 | 含义 |
|---|---|
| `RdpDeny` | `fDenyTSConnections` 原值（0=允许远程，1=禁止） |
| `TermStart` / `TermRunning` | TermService 启动类型 / 运行状态 |
| `LanmanStart` / `LanmanRunning` | LanmanServer 启动类型 / 运行状态 |
| `HibernateEnabled` | 休眠开关 |
| `NicPowerJson` | 各网卡节能设置（adapterName → 布尔值的 JSON） |
| `DefRdpGroupEnabled` / `DefSmbGroupEnabled` | 系统默认防火墙规则组启用状态 |
| `DefFwRulesWasEnabled` | 默认规则组的详细启用位 |
| `AutoStartExisted` / `AutoStartValue` | 开机自启项原值 |
| `Time` / `AppVersion` | 捕获时间 / 程序版本 |

> ⚠️ **P0 级陷阱：`System.Text.Json` 默认不序列化 public 字段，只认属性。**
> 早期 `RepairResult` / `ItemResult` / `SnapshotInfo` / `RepairSnapshot` 全部定义为 public 字段，导致落盘全是 2 字节的 `{}`。
> 更危险的是：**空快照若被用于恢复，会把系统按"默认值"重写**（关远程桌面、停服务、放开防火墙），在远程场景下等于自断连接。
> 现在有双重保护：① 全部改属性；② `ExplainInvalidSnapshot()` 校验（缺 Time / 缺 AppVersion / 缺 NicPowerJson 即拒绝执行）。

## 五、关键技术决策与理由

### 5.1 为什么用显式 DPI 换算，而不是 WinForms 的 `AutoScaleMode.Dpi`

> 本项目界面**全是纯代码构建，无设计器基准信息**。WinForms 自动缩放依赖设计时的 `AutoScaleDimensions`，在纯代码场景下行为难以预测且容易出现"双重缩放"。
> 显式换算行为完全确定、可被测试探针逐项测量验证。所有窗体统一设 `AutoScaleMode = None`，这是**设计契约**，新增窗体必须遵守。

配套约定（新窗体照抄）：

```csharp
// 1. 窗体尺寸
AutoScaleMode = AutoScaleMode.None;
UiScale.SetFormSize(this, 760, 520, 620, 420);   // 设计宽高 + 最小宽高

// 2. 按钮 —— 用 AutoFit 而非固定宽度（高 DPI 下中文变宽会切字）
btn.Width = UiScale.S(90);       // ❌ 固定宽度
btn.AutoFit(90);                  // ✅ 按文字实测宽度撑开

// 3. 列表列宽（末列自动补满）
UiScale.SetColumns(listView, (20, "名称"), (30, "地址"), (0, "备注"));

// 4. Padding / Height
panel.Padding = UiScale.S(new Padding(12));
```

> ⚠️ **WinForms 停靠陷阱**：**后添加的控件优先占边缘**。
> `Dock=Fill` 的控件必须**最先** `Controls.Add()`，否则会把后添加的 `Dock=Bottom` 面板挤没。
> 诊断窗体就踩过这个坑——详情面板整块消失。

### 5.2 为什么 `DiagnosticsService` 用 `netsh` 而不是 PowerShell cmdlet

实测（Windows 10 IoT 企业版 LTSC 19044）：

| 命令 | 结果 |
|---|---|
| `Get-NetFirewallRule` | **返回 0 条**（不可用） |
| `Get-NetAdapterPowerManagement` | **返回 0 条**（不可用） |
| `netsh advfirewall firewall show rule` | ✅ 可用 |

所以修复动作与快照检测全部走 netsh 通道，且**按规则名称逐条操作**（跨语言稳定，不依赖本地化组名）。

> ⚠️ **中文解码陷阱**：项目启用 `InvariantGlobalization=true` 时，`CultureInfo.CurrentCulture.TextInfo.OEMCodePage` 返回 **437**，而中文系统实际是 **936**。
> 这导致 netsh 中文输出被按错误代码页解码 → 防火墙检测全部失效（明明有规则却报"未检测到"）。
> 修复：改用 Win32 API `GetACP()` / `GetOEMCP()` 取真实代码页 + 双通道解码（先 OEM 后 ANSI，按乱码特征自动切换）。

### 5.3 为什么网卡节能修复要读注册表

读：`HKLM\SYSTEM\CurrentControlSet\Control\Class\{4d36e972-e325-11ce-bfc1-08002be10318}\<实例>\Device Parameters\PowerManagement\AllowComputerToTurnOffDevice`

写：优先 `Set-NetAdapterPowerManagement`，该 cmdlet 不可用时**回退到注册表写入**。

> 已知限制：某些驱动（USB 网卡 / 虚拟机网卡）不在注册表暴露该键，检测会报"未读取到网卡电源设置"。
> 修改后部分网卡需重启才生效，这是硬件/驱动限制，程序无法绕开。

### 5.4 为什么用 `--result` JSON 文件做父子进程 IPC

UAC 提权子进程是独立进程，标准输出/退出码不足以传递结构化结果（哪些项修好、为什么失败）。
所以子进程把 `RepairResult` 序列化成 JSON 写到指定路径，父进程读回。UAC 取消（`Win32Exception(1223)`）另做判定，统一返回 `UserCancelled`。

### 5.5 为什么提升权要"以自身 exe + 无界面模式"而不是单独的 helper

单文件发布下 `Application.ExecutablePath` 就是正确的 exe 路径，`runas` 拉起自身即可复用到所有 Services 代码，无需额外分发一个 helper 可执行文件。

## 六、安全设计

| 面 | 措施 |
|---|---|
| **网络暴露** | 3389/445 仅对 `100.64.0.0/10` 放行；**主动禁用**系统默认"远程桌面"/"文件共享"规则组（它们默认作用域是"任何地址"）；诊断项"安全强度"可核验 |
| **凭据存储** | 密码 DPAPI `CurrentUser` 加密；`secrets.json` Hidden + NTFS ACL 仅当前用户 |
| **凭据传递** | SMB 走 `CredWrite` 写系统凭据管理器；**绝不出现在命令行**（v1.6 移除 `cmdkey /pass:` 回退） |
| **RDP 认证** | `EnableCredSspSupport=true`（NLA）+ `AuthenticationLevel=2`（防中间人） |
| **数据流** | P2P 直连时画面不经过任何第三方服务器；走中继时端到端加密 |
| **破坏性操作** | 修复前强制快照；恢复前校验快照有效性（拒绝空/残缺快照）；文件传输原子替换 + 覆盖前确认 |

**UAC 边界**：程序只在"用户点击修复/恢复"时提权，不后台静默提权。提权子进程为无界面模式，执行完即退出。

## 七、已知架构限制（诚实清单）

| 限制 | 影响 | 是否可解 |
|---|---|---|
| 家庭版 Windows 不能当被控端 | 微软 SKU 级限制 | ❌ 无解（改注册表/补组件都绕不过） |
| RDP 连接时锁定被控端屏幕 | Windows 客户端 SKU 的会话模型 | ❌ 无解（需求已确认不需要同屏） |
| 部分网卡不暴露节能设置 | 该诊断项报"未知" | ⚠️ 驱动相关，无法完全覆盖 |
| 企业网严格限 UDP 时走中继 | 变慢（回到"限速"观感） | ⚠️ 换公司 VPN / ZeroTier |
| 诊断 15 项中有 3 项依赖网络状态 | 离线时结果不稳定 | ✅ 可接受（设计如此） |
| 无 ARM64 交付包 | ARM 设备需用 x64 版（走模拟） | ✅ 计划中（见路线图） |
| `PublishTrimmed=false` | 产物 161 MB | ⚠️ 为稳定性牺牲体积（WinForms + COM 反射裁剪风险高） |
