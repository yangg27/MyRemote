## 二、项目结构

两个工程，**共用一个源码基线**：

```
MyRemote/                主程序（WinExe，单文件自包含）
  MyRemote.csproj

MyRemote.Probe/          自检探针（Console，链接引用主程序源码）
  MyRemote.Probe.csproj
  Program.cs             入口 + 五种模式（--exec / --dump / --ui / --shot）
  FunctionalSelfTest.cs  490+ 项功能断言
  SnapshotProbe.cs       快照链路端到端验证
```

**探针的关键设计**：`csproj` 里用 `<Compile Include="..\MyRemote\**\*.cs" />` 直接**链接**主程序源码（排除 `Program.cs` 避免入口点冲突）。

> 这样保证**探针验证的就是生产代码本身**，而不是另写一份可能随时走样的副本。
> 代价：改主程序源码后探针需重新编译（一条命令的事）。

## 四、⭐ 发布单文件 exe（关键命令）

```bash
dotnet publish MyRemote/MyRemote.csproj -c Release -o <输出目录> \
  -p:IncludeNativeLibrariesForSelfExtract=true
```

### 🔴 必须带 `IncludeNativeLibrariesForSelfExtract`

**这是最容易踩的坑。** 不带这个参数时，6 个原生 DLL 会散落到输出目录：

```
D3DCompiler_47_cor3.dll
PenImc_cor3.dll
PresentationNative_cor3.dll
vcruntime140_cor3.dll
wpfgfx_cor3.dll
...
```

带上之后，所有原生库被打进单个 exe（体积从 ~150MB 变成 ~161MB，但**真正单文件**）。

> 症状识别：如果你发现发布目录里除了 exe 还有一堆 DLL，就是漏了这个参数。
> 交付形态必须是**单个 exe**，否则用户拷贝时容易漏文件。

### csproj 中的相关配置

```xml
<RuntimeIdentifier>win-x64</RuntimeIdentifier>
<SelfContained>true</SelfContained>              <!-- 用户无需装 .NET 运行时 -->
<PublishSingleFile>true</PublishSingleFile>
<PublishTrimmed>false</PublishTrimmed>           <!-- 必须 false：WinForms + COM 反射裁剪风险高 -->
<InvariantGlobalization>true</InvariantGlobalization>
<AllowUnsafeBlocks>true</AllowUnsafeBlocks>
<EnableWindowsTargeting>true</EnableWindowsTargeting>  <!-- 支持在非 Windows 环境构建 -->
```

> **关于 `PublishTrimmed=false`**：产物 161 MB 确实大，但开启裁剪后 COM 后期绑定（`Type.GetTypeFromProgID` + 反射）可能因类型被裁掉而运行期失败，WinForms 设计器相关类型也容易被误裁。为稳定性放弃体积优化。

## 五、⭐ 验证（改动后必做）

### 5.1 功能自检（490 项断言）

```bash
cd MyRemote.Probe/bin/Release/net8.0-windows/win-x64
./MyRemote.Probe.exe --func
```

输出末尾会打印汇总：

```
自检汇总：通过 490 ｜ 失败 0 ｜ 跳过 1
```

**测试隔离机制**：探针启动时设置 `AppPaths.OverrideDir = <临时沙箱目录>`，所有设备/凭据/日志/快照测试都写在临时目录，**绝不碰用户的真实配置**。同时通过以下开关抑制 UI 副作用：

```csharp
MainForm.CreateTrayIcon = false;         // 不创建托盘图标
SessionForm.AutoConnectOnShown = false;  // 不自动发起真实 RDP 连接
```

覆盖范围：DeviceStore CRUD/备份/损坏恢复、CredentialVault、Tailscale 三层读取、RDP CLSID 探测、PackageService、RepairService 序列化往返、UiScale 数学、AppPaths、SystemLog、LocalMachineInfo、全部窗体实例化、并发与健壮性。

### 5.2 界面布局审计

```bash
# 默认（当前系统 DPI）
./MyRemote.Probe.exe --ui

# 模拟指定缩放与屏幕尺寸
MYREMOTE_UI_SCALE=1.5 MYREMOTE_UI_SCREEN=1366x768 ./MyRemote.Probe.exe --ui
```

审计内容：①窗体是否超屏 ②子控件是否溢出容器 ③工具条是否把按钮藏进溢出菜单 ④按钮文字是否被切（`TextRenderer` 实测宽度）。

> **模拟模式下字体同步放大** —— 真实高 DPI 下 GDI+ 会放大 pt 字体，只放大控件尺寸会漏检"字变大 → 按钮切字"。
>
> **踩坑记录**：`ScaleFonts` 递归时，未显式设置字体的子控件会返回父控件的同一字体引用，逐层重复放大导致指数级失真（2.5×2.5）。
> 修复：`ReferenceEquals(f, inheritedFrom)` 时跳过继承字体。

**建议的验证矩阵**（全部应为"未发现溢出或超出屏幕"）：

| 缩放 | 屏幕尺寸 |
|---|---|
| 100% | 1920×1080 |
| 125% | 1366×768 |
| 150% | 1366×768 |
| 200% | 1920×1080 |
| 300% | 1280×720 |
| 400% | 1920×1080 |

### 5.3 快照链路端到端

```bash
./MyRemote.Probe.exe --snapshot
```

验证：真实捕获系统快照 → 落盘 JSON 含全部关键字段（`RdpDeny` / `TermStart` / `DefFwRulesWasEnabled` / `NicPowerJson` 等）→ `ListSnapshots()` 能识别。

**这是 P0 序列化缺陷的回归测试**。若输出显示"文件大小：2 字节"，说明序列化又退化成字段了（见 [迭代历史](迭代历史.md) 的 P0 章节）。

### 5.4 界面截图（人工核对）

```bash
./MyRemote.Probe.exe --shot ./screenshots
```

用 `DrawToBitmap` 渲染每个窗体为 PNG，人工核对视觉效果。

### 5.5 诊断/修复链路（只读）

```bash
./MyRemote.Probe.exe            # 只读模式：检查 Tailscale / RDP 控件 / 端口连通性，不做任何修改
./MyRemote.Probe.exe --exec     # 执行模式：含写入操作（仅在确认要真机验证修复时使用）
./MyRemote.Probe.exe --dump     # 取证模式：转储底层命令原始输出（排查编码/格式问题）
```

## 六、发布交付包

### 6.1 交付目录结构

```
MyRemote-Delivery/
├── MyRemote.exe                        主程序（161 MB，单文件自包含）
├── packages/
│   └── tailscale-setup-1.104.1.exe     内置安装包（程序自动使用）
└── 使用说明.txt                         面向最终用户的简短说明
```

### 6.2 打包命令（PowerShell）

```powershell
Compress-Archive -Path ".\MyRemote.exe",".\packages",".\使用说明.txt" `
  -DestinationPath "..\MyRemote-vX.Y-Delivery.zip" -CompressionLevel Optimal
```

结果约 63 MB（exe 本身压缩率很高）。

### 6.3 打包后必做校验

```bash
# ① 列出 zip 内容（确认文件齐全）
unzip -l MyRemote-v1.7-Delivery.zip

# ② 解压验证（确认中文文件名未损坏、exe 哈希一致）
md5sum <解压目录>/MyRemote.exe
md5sum MyRemote-Delivery/MyRemote.exe    # 两者必须一致
```

> ⚠️ **中文文件名陷阱**：在 Git Bash 里 `unzip -l` 可能显示 `使用说明.txt` 为乱码。**这是终端编码问题，不代表 zip 损坏。**
> 用 PowerShell 的 `Expand-Archive` 解压后检查真实文件名即可确认。

### 6.4 GitHub 发布的体积限制（重要）

| 文件 | 体积 | 能否直接进 Git 仓库 |
|---|---:|---|
| `MyRemote.exe` | 161 MB | ❌ **超过 GitHub 单文件 100 MB 硬限制** |
| `MyRemote-v1.7-Delivery.zip` | 63 MB | ✅ 可以 |

**所以交付物以 zip 形式进仓库，不要把裸 exe 提交进 Git 历史。** 若确实需要分发裸 exe，用 GitHub Releases（支持大文件，单文件上限 2 GB）。

## 七、发布前后检查清单

```
□ dotnet build 零警告零错误
□ MyRemote.Probe.exe --func         → 0 失败
□ MyRemote.Probe.exe --ui           → 无溢出（至少测 100% 与 150%）
□ MyRemote.Probe.exe --snapshot     → 快照 JSON 非空（> 100 字节）
□ 交付目录的 exe 是最新发布产物（对比时间戳，别交付了旧版）
□ publish 带了 IncludeNativeLibrariesForSelfExtract（输出目录无散落 DLL）
□ zip 解压后 exe 哈希与交付目录一致
□ 使用说明.txt 已同步最新改动
□【可选】GUI 冒烟：双击 exe → 进程存活 → 关闭
□【可选】负面测试：用空快照执行 --restore → 必须被拒绝
```

### GUI 冒烟测试（命令行）

```bash
./MyRemote.exe &
sleep 4
tasklist //FI "IMAGENAME eq MyRemote.exe"    # 确认进程存活
taskkill //F //IM MyRemote.exe
```

启动日志会记录界面自适应信息，可核对：

```bash
tail -5 "%APPDATA%\MyRemote\MyRemote.log"
# 期望含：[启动] 界面自适应：100%（系统 DPI 96），屏幕可用区域 1920x1040
```

### 负面测试（验证安全防护有效）

```bash
# 构造一个空快照（{}），尝试恢复 —— 必须被拒绝且不改动系统
echo '{}' > /tmp/empty.json
./MyRemote.exe --restore --snapshot "C:\path\to\empty.json" --result "C:\path\to\result.json"
cat result.json
# 期望：{"Success":false,"Message":"快照不可用：...已中止恢复，未改动任何系统设置。"}
```

## 八、构建/发布踩坑总清单

| # | 坑 | 症状 | 解决 |
|---|---|---|---|
| 1 | 漏 `IncludeNativeLibrariesForSelfExtract` | 输出目录散落 6 个原生 DLL | 发布命令必须带该参数 |
| 2 | `System.Text.Json` 不序列化 public 字段 | 结果/快照文件是 2 字节 `{}` | 数据类**必须用属性** `{ get; set; }`，不能用字段 |
| 3 | 环境有 http 代理时 pip 失败 | 403 | 显式用官方源（见下方） |
| 4 | 发布产物未更新就打包 | 交付了旧版 exe | 对比源码与 exe 时间戳 |
| 5 | zip 中文文件名在 bash 显示乱码 | 误以为损坏 | 用 PowerShell `Expand-Archive` 验证真实文件名 |
| 6 | 单文件 exe 首启动稍慢 | 用户以为卡死 | 属正常（需解压到临时目录），已在说明中提示 |
| 7 | `File.Replace` 要求目标存在 | 首次保存设备崩溃 | 目标不存在时用 `File.Move` |
| 8 | `InvariantGlobalization=true` 下代码页错误 | 中文系统命令输出乱码 | 用 `GetACP()`/`GetOEMCP()` Win32 API 取真实代码页 |
| 9 | PowerShell 脚本 UTF-8 无 BOM 被按 ANSI 解析 | 中文网卡名乱码 | 写临时 .ps1 时用 **UTF-8 BOM**；或改用 `-EncodedCommand` |

### Python 环境与依赖安装（若需辅助脚本）

## 十、代码约定（新增代码请遵守）

| 约定 | 说明 |
|---|---|
| **窗体尺寸** | 用 `UiScale.SetFormSize()`，不要写死 `Width`/`Height`/`MinimumSize` |
| **按钮宽度** | 用 `.AutoFit(minWidth)`，不要用固定 `Width`（高 DPI 会切字） |
| **窗体缩放模式** | 必须 `AutoScaleMode = AutoScaleMode.None` |
| **停靠顺序** | `Dock=Fill` 的控件必须**最先** `Controls.Add()` |
| **数据类** | 需序列化的类**必须用属性**（`{ get; set; }`），不能用 public 字段 |
| **日志** | 用 `SystemLog.Info/Warn/Error/Exception`，不要 `Console.WriteLine` |
| **异常处理** | 允许宽容 catch（程序不易崩），但**关键路径要写日志**（便于排查） |
| **线程安全** | 跨线程更新 UI 前检查 `IsDisposed`/`IsHandleCreated` |
| **资源释放** | COM 对象/图标句柄要显式释放（`Dispose` / `DestroyIcon`） |
