## 一句话结论

你要的不是"从零写一个远程桌面协议"，而是**一个连接管理器**：用虚拟组网把**多台**机器拉进同一个虚拟局域网，远程桌面交给 Windows 原生的 RDP，文件传输交给 Windows 原生的 SMB，你只需要写"设备面板 + 会话宿主 + 文件管理器 UI"这三块。

**网络层已于 2026-10-18 最终锁定为：Tailscale 官方免费版**（WireGuard 内核、数据 P2P 直连、客户端 BSD-3 开源、控制面在其官方、免费额度 1 用户 + 无限设备）。你已明确"可接受安全合规的开源软件"并"接受 Tailscale"。这意味着此前纠结的"公网 IPv4 / CGNAT / 自架 hub"全部不再是前置条件——**装好 Tailscale 三台互相就能找到，零端口映射、零 DDNS、零自架服务器**。

## 2.2 由需求派生的硬性要求（必须做，否则无人值守会失败）

| 要求 | 原因 |
|---|---|
| 远控账号必须使用**密码**登录 | Windows Hello **PIN / 指纹 / 人脸无法用于远程认证**——这是"明明开了远程就是连不上"的头号原因 |
| 密码**不能为空** | 空密码账户被 Windows 默认禁止远程登录 |
| 关闭睡眠 / 休眠 / 合盖睡眠 | 机器睡过去就永久失联 |
| 关闭网卡"允许关闭此设备以节约电源" | 是"隔几天就断连"的头号元凶 |
| BitLocker 用 **TPM 自动解锁**，不加开机 PIN | 加了 PIN 则重启后无法远程进入系统 |
| **不需要**设置系统自动登录 | TermService 是系统级服务，开机即可接受连接，无需先有人登录 |
| 记录远程用的**用户名** | 不是 PIN，是用户名（`whoami` 可查） |

# 第三部分：已核实的关键事实（可查证）

## 3.1 Windows 远程桌面（RDP）

| 事实 | 说明 |
|---|---|
| 家庭版**不能作为 RDP 被控端** | 这是微软 SKU 级的产品分级限制，改注册表、补组件都无法绕过。家庭版只有 mstsc 客户端 |
| RDP 连接时会**锁定被控端本地屏幕** | 这是 Windows 客户端版 SKU 的会话模型（非技术缺陷）。已确认不需要同屏，故无影响 |
| RDP 自带 | 多显示器、分辨率自适应、剪贴板同步、音频 / 打印机重定向、GPU 加速、UDP 传输 |
| 家庭版的"远程协助"不是一回事 | 需对方现场点"接受邀请"，无法无人值守 |
| 升级专业版是**就地解锁**，不删文件软件 | 但**不可逆**，事后想回家庭版只能重装 |

## 3.3 隐私边界（已核实）

- **控制面**走官方服务器：仅交换"对方在哪、公钥是什么"等元数据，**不含画面内容**

# 第五部分：每一层怎么落地

## 5.0 第 0 层：虚拟组网 = Tailscale 官方免费版（已锁定）

**选型结论**：放弃此前讨论的 WireGuard 自架 hub / 自建 Headscale 路线，采用 **Tailscale 官方免费版**。

**为什么这是最终答案**：
- 你已确认"不希望有公网 IP / 纯 IPv4 / 不买服务器" → 自架方案的物理前提（公网可达的 hub）不存在
- Tailscale 通过**被控端主动出站**建立隧道，完美绕过"企业 Wi-Fi 入站被封""家庭无公网 IP"两道坎
- 免费额度 **$0、1 用户、设备数无限**，3 台机器绰绰有余
- 客户端源码 BSD-3 开源，底层 WireGuard 内核级，数据 P2P 直连时**完全不过官方服务器**

**接入方式（每台机器一次性）**：
1. 安装 Tailscale，登录**同一个账号**
2. 三台各自获得固定虚拟 IP（`100.x.x.x`）+ 机器名（MagicDNS）
3. 互相之间用虚拟 IP 或机器名即可访问——RDP 连 `100.x.x.x:3389`、SMB 连 `\\100.x.x.x\共享`

> ⚠️ **重要纠偏（"常开电脑"不再构成网络前提）**：此前在讨论 WireGuard 自架 hub 时，"家里常开一台"是拓扑刚需。但采用 Tailscale 后，**三台机器完全对等，没有中心节点**，谁被控谁就要开机，不存在"必须有一台常开当 hub"。你"可保持一台常开"只是顺手能力，并非强制——它只是保证"你随时想连的那台在线上"，与网络打洞无关。

**新增设备（如新买的电脑）的加入流程**：在 Tailscale 免费计划下**设备数无限**，加机器零成本、零改架构——
1. 新电脑装 Tailscale，登录**同一个账号**（自动进同一虚拟网，拿到新 `100.x.x.x`）
2. 新电脑装 `MyRemote.exe`，在设备面板点"添加设备"，填入它的虚拟 IP / 机器名 + 远控用户名
3. 跑一次 `一键部署.ps1` 固化被控端（开 RDP、关休眠、配 SMB、存凭据）
4. 完成——立即可作为控制端或被控端使用，无需改动任何核心代码

**风险提示（诚实告知）**：
- 企业网若做严格出站白名单（只放行 80/443），UDP 打洞会退化或失败 → 此时优先改用公司官方 VPN
- 境外控制面偶尔握手慢 → 仅影响"建连那一瞬"，P2P 打通后数据流走两家宽带之间，与境外无关
- DERP 中继兜底时数据经官方服务器但**端到端加密**，官方无法解密、看不到屏幕内容

## 5.1 第 1 层：远程桌面（Windows RDP）

**实现方式**：使用微软官方 **MsRdpClient ActiveX 控件** 嵌入自研窗口，而不是调用独立的 mstsc 窗口。

> **关键技术决策**：采用 **COM 后期绑定**（`Type.GetTypeFromProgID` + `Activator.CreateInstance` + 反射调用），而非编译期 COM 引用。原因是编译期引用 Windows COM 组件需要 `tlbimp`，无法在非 Windows 环境完成；后期绑定可支持在 Linux 构建机交叉编译出 Windows 可执行文件——这是"交付成品 exe、你无需安装任何开发工具"这一交付形态的前提。

**关键配置项**：

| 用途 | 属性 |
|---|---|
| 目标 / 凭据 | `Server`、`UserName`、`AdvancedSettings9.ClearTextPassword` |
| 文件 / 剪贴板 / 打印机重定向 | `AdvancedSettings9.RedirectDrives`、`RedirectClipboard`、`RedirectPrinters` |
| 窗口自适应缩放 | `AdvancedSettings9.SmartSizing = true` |
| **防中间人** | `AdvancedSettings9.AuthenticationLevel = 2` |
| **网络级别认证 (NLA)** | `AdvancedSettings9.EnableCredSspSupport = true` |
| 画质 | `ColorDepth = 32`、`DesktopWidth / DesktopHeight` |
| 事件 | `OnConnected` / `OnDisconnected` / `OnLoginComplete` / `OnFatalError` |

## 5.2 第 2 层：文件管理（独立窗口）

**方案：SMB over 虚拟内网**

虚拟组网已让 3 台机器处于同一虚拟局域网，可直接复用 **Windows SMB** 作为文件传输引擎。

**为什么不用 RDP 的磁盘重定向**：它依附于远程桌面会话——必须建立会话、拖拽必须在会话窗口内、无法独立后台传输。你明确要求"独立窗口"，故选 SMB。

**优点**：
- 独立于远程桌面会话，不开远控也能传文件
- 引擎成熟（传输、缓存、并发、错误恢复由 Windows 负责）
- 安全能力内建（SMB 3.1.1 支持 AES-128-GCM 加密与签名）
- 走虚拟内网直连，无中转

**自研部分**：
```
文件管理窗口
├── 左栏：本地文件系统树 + 拖拽接收
├── 右栏：远程 UNC 路径（\\<虚拟IP>\<共享名>）
├── 传输引擎：分块读写 + 进度回调（自研，以支持进度条）
├── 任务队列：多线程 / 暂停 / 取消
└── 可选：断点续传（后续版本）
```

**被控端需具备的条件**（由部署脚本自动完成）：
1. 启用 SMB 共享（可用管理员默认共享，或建专用共享）
2. **防火墙作用域限定**：文件共享放行规则仅对虚拟网卡网段生效
3. 凭据预存至 Windows 凭据管理器（**CredWrite P/Invoke**，不暴露明文命令行）

> ⚠️ **安全红线**：**445 端口绝对不得暴露至公网。** SMB 是永恒之蓝（EternalBlue）等蠕虫的主要传播面，公网裸奔 SMB 会在极短时间内被自动化攻击。放行规则的作用域必须严格限定为虚拟网卡网段。

# 第八部分：可行性边界（说真话）

## 8.1 什么情况下"不限速"能真正成立（当前选定路径）

**采用 Tailscale，绝大多数家庭 / 公司网络下 P2P 直连成功**：
- WireGuard 内核打洞，两端通过 Tailscale 控制面"握手认识"后，数据流**直接在两家宽带之间跑**
- 带宽天花板 = 两端的上下行宽带，**没有施加"限速"的第三方**
- 只要 `tailscale ping <对方>` 显示 `direct`，就是真·不限速——这也是官方软件绝不会告诉你的指标

> 一个反直觉但重要的点：你家里两台在同一局域网，所以"中转"几乎不损失带宽。真正瓶颈从来只在跨网那一跳，无论是否 P2P 直连都存在。

## 8.2 什么情况下达不到"不限速"（兜底现实）

**企业网严格限制 UDP 出网 / 对称型 NAT，导致 P2P 打洞失败**：
- 此时 Tailscale 自动退化到官方 **DERP 中继**，数据经境外服务器折返 → 会重新出现"限速 + 高延迟"观感
- 这是免费版的唯一代价，也是你最初想逃离的处境的"缩水版"
- **应对阶梯**：① 先试公司官方 VPN（合规最稳）② 换 ZeroTier（可配国内 Moon）③ 极端情况再考虑大带宽 VPS 自建
- **这不是能力问题，是网络环境限制**。在"纯 IPv4 + 不买服务器"前提下，Tailscale 免费版已是性价比最高的解。

## 8.3 已排除的风险项

| 风险 | 处理 |
|---|---|
| 家庭版不能当 RDP 被控 | 已决定升级专业版 |
| RDP 会锁屏 | 已确认不需要同屏 |
| 用 PIN 登录导致连不上 | 已在部署清单中列为硬要求 |
| 机器休眠导致失联 | 已在部署清单中列为硬要求 |
| 445 / 3389 暴露公网 | 防火墙作用域严格限定虚拟网卡网段 |
| 逆向 Tailscale 的合规风险 | **不需要**——源码 BSD-3 公开，合法复用即可 |

## v1.6 复测与缺陷修复记录（2026-10-18）

对全部源码做了一次逐文件复测（16 个源文件 + 部署脚本），编译零警告零错误，共修复 19 处问题，按严重度归档：

### 一、致命（功能直接不可用）

1. **首次保存设备必崩**：`DeviceStore.Save` 用 `File.Replace`，该 API 要求目标文件已存在；第一次"添加设备"时 `devices.json` 尚不存在，直接抛 `FileNotFoundException`。改为不存在时 `File.Move`。
2. **文件管理免密失效**：`NetworkShareHelper` 用 UTF-8 编码密码写入 `CRED_TYPE_DOMAIN_PASSWORD` 凭据。该类型要求 **UTF-16**，UTF-8 字节会被按 UTF-16 解释成乱码，等于存了个错误密码。改为 `Encoding.Unicode`，并加 512 字节长度上限校验。

### 二、安全

3. **移除 cmdkey 明文回退**：`AddCredential` 失败时曾回退 `cmdkey /pass:xxx`，会把密码暴露在进程命令行。改为仅记日志。
4. **防火墙暴露判定修正**：只要存在一条 `RemoteAddress=Any` 的 3389 放行规则即告警（旧逻辑"存在 Tailscale 规则就判安全"会掩盖真实暴露）。
5. **一键恢复的状态判断修正**：`DefaultGroupEnabled` 旧实现只要输出里出现"已启用"就返回 true（每个规则块都有该行，值为"否"时也有），导致快照记录的默认组状态几乎总是"已启用"，恢复时可能重新放开 Any 作用域。改为逐块解析"已启用 是/否"。

### 三、正确性（中文系统环境）

6. **中文版专业版被判为家庭版**：旧逻辑在 `ProductName` 里找 "Pro"，而中文系统是"Windows 10 专业版"。改用与语言无关的 `EditionID`，并保留中英文名称关键字回退。
7. **休眠检测误判**：旧逻辑解析 `powercfg /hibernate query` 输出中的 "enabled"，中文系统输出"休眠已启用"。改为读注册表 `HibernateEnabled`。
8. **防火墙检测把"已禁用"当"已放行"**：新增 `BlockEnabled` / `BlockAllows` 按行解析，只有"已启用 且 允许"才算放行。这直接决定一键修复后能否变绿。
9. **PowerShell 脚本中文乱码**：`RunPsFile` 用 UTF-8 无 BOM 写临时脚本，PowerShell 5.1 按系统 ANSI 解析，中文网卡名变乱码。改为 UTF-8 **BOM**。
10. **网卡节能快照单适配器解析失败**：`ConvertTo-Json` 对单元素数组会展开成对象。改为哈希表汇总输出稳定的 JSON 对象。
11. **Tailscale 导入可能取到 IPv6**：改为在 `TailscaleIPs` 中优先取含 "." 的 IPv4。

### 四、稳定性

12. **自动重连次数被秒耗尽**：状态轮询每秒都调用 `ScheduleAutoReconnect`，每次都累加次数并重建定时器，5 次机会 5 秒内用完。新增 `_reconnectPending` 闸门，且重连时重置 `_connectedOnce` 使看门狗同样生效。
13. **重连泄漏 COM 对象**：`InternalDisconnect` 现在会从面板移除并 `Dispose` 旧 `RdpHost`，再置空引用。
14. **文件传输可能留下半截文件/覆盖原文件**：改为写 `.mrtmp` 临时文件 → 校验大小 → `File.Move(..., overwrite:true)`；失败或取消时删除临时文件，目标保持原状。
15. **覆盖/合并无提示**：传输前列出同名目标并二次确认。
16. **无界面修复子进程弹窗卡死父进程**：`_headless` 下全局异常只写日志不弹窗。
17. **UAC 取消被当成失败**：捕获 `Win32Exception(1223)` 与"操作已被用户取消"，统一返回 `UserCancelled`，UI 提示"已取消"。
18. **单实例互斥可能打不开程序**：改为 `Local\` → `Global\` → 无前缀三级降级，全部失败也放行启动。
19. **其它**：配置损坏时另存 `.corrupt-时间戳` 现场；`secrets.json` 原子写入；图标 `GetHicon` 句柄 `DestroyIcon` 释放；日志查看器改增量刷新并停止定时器；诊断的 `netsh` 防火墙输出单次复用；Tailscale 导入改 `Shown` 后异步加载；删除设备/改地址时同步清理系统凭据；设备端口做 1–65535 校验；主窗体在线探测的跨线程更新加兜底。

> 说明：以上均为静态复测 + 交叉编译验证（Linux 沙箱无法实跑 Windows 运行时），涉及 UAC 提权、网卡节能、SMB 认证等路径仍需在真机点一次确认。
